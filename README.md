# BFWAI AI Inventory Decision Agent (Person 1 Pipeline)

An AI-driven customer-data-driven inventory decision support system designed for demand forecasting, feature engineering, Gemini + NewsAPI market intelligence, and product intelligence orchestration.

## Customer-Data-Driven Architecture

1. **Customer Data Input**:
   - Primary upload: `data/input/customer_inventory_upload.csv`
   - Demo/sample upload: `data/input/customer_inventory_upload_sample.csv`
   - The customer provides historical sales and inventory data only.
   - **The customer does NOT need to provide market signals, search trends, news, or forecasting decisions.** Any customer-provided `market_signal` or forecast fields are automatically ignored and dropped.

2. **Customer-Specific Demand Forecasting**:
   - **The forecasting model is trained/adapted using the customer's uploaded historical data.**
   - The system NEVER uses or overwrites the baseline development model (`models/demand_forecasting_model.pkl`).
   - Customer-trained models are saved independently under `models/customer/customer_demand_model.pkl`.
   - Generates 7-day forecast (`forecast_7d`), 30-day forecast (`forecast_30d`), and `sales_trend`.

3. **External Market Intelligence (Gemini + NewsAPI)**:
   - **Market intelligence is obtained separately through external news data and Gemini.**
   - Pipeline: `Product Metadata -> Keywords -> NewsAPI -> Articles -> Gemini API -> Structured Market Signal`.
   - Generates `market_signal`, `market_impact`, `market_confidence`, `market_relevance`, `evidence_strength`, `evidence_summary`, `reason`, `key_events`, `risks`, and `opportunities`.
   - If news articles are unavailable or insufficient, defaults to `market_signal = "neutral"` and `external_signal_available = false`.

4. **Product Intelligence Handoff (`product_intelligence.csv`)**:
   - The official interface file generated by Person 1 for Person 2 is:
     `BFWAI/outputs/predictions/product_intelligence.csv`
   - Combines product metadata, customer-trained forecasts, current inventory levels, supplier specifications, and external market intelligence into a single product-level file.

5. **Decision Engine Separation**:
   - **The final inventory decision is handled by a separate decision engine (Person 2).**
   - Person 1 does NOT generate inventory decisions (`INCREASE`, `MAINTAIN`, `REDUCE`) or recommended order quantities.

# Person 2: AI Inventory Decision Agent & Dashboard

Person 2 consumes the output generated by Person 1 (`handoff/person2_handoff.json`) and answers the core operational question:

> **"Given what is likely to happen, what should the seller do?"**

```text
Person 1 Pipeline (Forecasting + Market Intelligence)
                        ↓
             handoff/person2_handoff.json
                        ↓
                 PERSON 2 BACKEND
                        ↓
            1. Inventory Analysis
               (DOS, Coverage, Safety Stock, Reorder Point, Stockout Risk)
                        ↓
            2. Multi-Signal Decision Engine
               (INCREASE / MAINTAIN / REDUCE + MOQ Recommended Order)
                        ↓
            3. AI Explanation Agent (Gemini / Deterministic Fallback)
                        ↓
            4. Alternative Product Recommendations (Capital Re-allocation)
                        ↓
                 FRONTEND DASHBOARD (React + Vite)
                        ↓
            5. Human-in-the-Loop Oversight (APPROVE / MODIFY / REJECT)
```

## 1. Inventory Analysis Calculations

All inventory metrics are dynamically calculated using transparent, explainable supply chain formulas:

### A. Available Inventory
```text
available_inventory = max(0, current_inventory - reserved_inventory)
```
*Accounts for physical on-hand stock minus existing customer commitments. Incoming stock is tracked separately in transit.*

### B. Average Daily Demand
```text
average_daily_demand = forecast_7d / 7.0  (or forecast_30d / 30.0)
```
*Safely handles zero demand without division by zero.*

### C. Days of Stock (DOS) & Coverage Ratio
```text
days_of_stock = available_inventory / average_daily_demand
coverage_ratio = days_of_stock / supplier_lead_time_days
```
*If daily demand is 0, stock is represented as safe 999.0 days (or 0 if on-hand is 0).*

### D. Safety Stock Heuristic
```text
safety_stock = ceil(1.65 × sqrt(lead_time_days) × average_daily_demand)
```
*Standard 95% service-level buffer absorbing lead-time demand volatility.*

### E. Reorder Point (Person 1 vs Fallback)
```text
reorder_point = (average_daily_demand × lead_time_days) + safety_stock
```
*Uses Person 1's provided `reorder_point` when present; otherwise calculates an explainable fallback.*

### F. Dynamic Stockout Risk (Explainable Heuristic)
Defined centrally in `STOCKOUT_RISK_CONFIG`:
* **HIGH**: `days_of_stock < supplier_lead_time` (inventory runs out before replenishment can arrive), or inventory breached reorder point under accelerating demand.
* **MEDIUM**: `days_of_stock` close to lead time (coverage ratio between 1.0x and 1.75x), or incoming stock mitigates an imminent stockout.
* **LOW**: `days_of_stock` comfortably exceeds lead time (coverage ratio ≥ 1.75x) with stable/decreasing demand.

### G. Recommended Order Quantity (MOQ-Respecting)
```text
Gross Requirement = Demand Horizon (30d) + Safety Stock
Net Requirement   = Gross Requirement - Available Inventory - Incoming Inventory

If Net Requirement <= 0:
    recommended_order_quantity = 0
Else:
    recommended_order_quantity = ceil(Net Requirement / MOQ) × MOQ
```
*Example: Net requirement of 73 units with MOQ of 50 dynamically recommends 100 units.*

## 2. Deterministic Decision Engine

The decision engine produces one of three unambiguous decisions:

```text
INCREASE  |  MAINTAIN  |  REDUCE
```

### Transparent Scoring Logic:
1. **Demand Factor (-0.30 to +0.30)**: Driven by 7d/30d forecast velocity and sales trend.
2. **Inventory Coverage Factor (-0.40 to +0.40)**: Driven by coverage ratio vs supplier lead time.
3. **Stockout Risk Factor (-0.10 to +0.30)**: Driven by calculated risk tier.
4. **Reorder Point Factor (0.0 to +0.25)**: Triggered when available inventory breaches reorder point.
5. **Market Intelligence Factor (-0.15 to +0.15)**: Bounded influence from external sentiment; never sole decider.

```text
Composite Score >= +0.25  →  INCREASE
Composite Score <= -0.25  →  REDUCE
Between -0.25 and +0.25   →  MAINTAIN
```

### Decision Confidence Score:
Reflects degree of alignment among signals (0.50 to 0.98). When demand, inventory, and market indicators point in the same direction, confidence is high; when signals conflict, confidence appropriately moderates.

## 3. LLM Explanation Agent

* **Role**: Translates quantitative outputs into human-readable executive narratives.
* **Architectural Rule**: The LLM **never** determines the numeric decision or order quantity.
* **Resilience**: Operates seamlessly offline or without API keys via deterministic fallback generator. Live Gemini generation activates automatically if `GEMINI_API_KEY` is provided.

---

## 4. Alternative Product Recommendations

For products with a `REDUCE` recommendation or high inventory overhang:
* Evaluates catalog items within the same category or higher velocity tiers.
* Identifies SKUs with increasing demand trends and healthy inventory turnover.
* Provides operational suggestions to re-allocate working capital without automated re-ordering.

---

## 5. Human-in-the-Loop Approval

* **[ APPROVE ]**: Concurs with AI-recommended order quantity.
* **[ MODIFY ]**: Allows inventory manager to adjust order quantity and record justification notes.
* **[ REJECT ]**: Dismisses replenishment order (sets order to 0 units).
* *Note: Does not place external vendor orders; maintains human decision authority.*
